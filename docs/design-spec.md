# lazy-ease design specification

**The design of 0.3, as implemented.** The root and package READMEs describe the 0.3 API. The [0.2 design](https://github.com/mikekuss/lazy-ease/blob/6c9043f37909bc8af6c8ab64782b13cc9f510c00/docs/design-spec.md) records the baseline, including the focal-window math, prop precedence and existing loader API. This document governs 0.3. See the [recipes](image-recipes.md), [backend contract in practice](backend.md) and [migration guide](migrating-from-0.2.md).

## Packages and cost

All public packages share one release version. Core exports pure functions and a framework-free controller. Vanilla depends on core and supplies HTML enhancement, CSS as a file and string, and a self-starting script. React depends on core and retains its framework peers. Server uses core's ladders, number formatting and crop geometry. Testing publishes JS helpers and portable JSON fixtures, also attached to each release. Multiple instances and copies can coexist on one page.

ESM imports must perform no detection, DOM access, observer setup or ladder computation. Use functions, static ladder data and lazy initialization. Keep optional ThumbHash decoding in an explicit entry point. A browser ESM import must work without a Node process global. The standalone IIFE is explicitly activated by its script tag. Preserve stylesheet imports in production bundles.

Measure each public import plus required core code with a pinned minifying bundler, production defines, external React peers and Brotli quality 11: esbuild 0.28.2, ES2022 ESM. The measurement fixtures are in `scripts/sizes`; `pnpm check:sizes` measures them after `pnpm build` and fails over budget or with another esbuild version (`--details` lists each entry's largest inputs, `--packed` measures the tarballs `pnpm check:packages` packed, `--json <file>` writes the results).

## Loading and markup

Source selection and display timing are independent. A template can generate all URLs and still request a fade.

| Mode | HTML before activation | Owner after activation |
| --- | --- | --- |
| Prepared fade | Inline placeholder and deferred candidates or single URL | Controller copies the supplied values on intersection. It needs no loader or layout read for a prepared slot. |
| Measured fade | Inline placeholder and logical source | Controller measures the slot, calls the loader and installs candidates. |
| Native / priority | Real sources and sizes in the initial HTML | Author or framework owns the sources. The browser discovers and displays them directly. |
| Decorative background | Placeholder rule and a visibility-gated CSS rule | JS sets the visibility marker once. CSS selects the image. |

A marked image or its nearest marked box owns one logical image, possibly inside picture. Use img.closest('[data-le]') within its tree. The template supplies every DOM node. Default to a box with an inline background-color placeholder (React: `#e5e7eb`); a data URI or ThumbHash placeholder is opt-in. Support boxless native images with a color, or a deferred boxless image with a data-URI source and hard swap. For boxed deferred images, an inert inline image source makes the initial img valid. Its load, complete flag and dimensions describe the placeholder until the target is assigned. A box is required for a crossfade, fill, browser focal positioning or explicit React wrapper props. Supply alt on img. Reserve geometry at first paint using dimensions, aspect-ratio or the positioned fill parent. Document CSP requirements for data images and inline styles, and support author CSS for placeholders and geometry.

| HTML field | Meaning |
| --- | --- |
| data-le | Marker on the box or img. The default IIFE scans only explicitly opted-in areas (data-le-auto on their root). data-le-auto="off" keeps a framework-managed subtree out of every scan. |
| data-le-srcset / data-le-sizes | Precomputed candidate list and slot. Activate sizes before srcset. |
| data-le-url | Precomputed single target URL. Use when dimensions are unknown or for pass-through. |
| data-le-src | Logical source for the configured measured loader. |
| data-le-srcw / data-le-srch | Oriented source dimensions. |
| data-le-ar / data-le-fill / data-le-crop | Layout ratio, boolean fill and server or browser crop. Native width and height remain meaningful HTML dimensions. |
| data-le-fx / data-le-fy | Optional focal coordinates in percent, supplied together. |
| data-le-token / data-le-v / data-le-q | Optional crop token, revision and quality passed to the loader. |
| data-le-background | Marks a decorative element whose CSS gates its image on data-le-visible. |
| data-state / data-le-visible | Controller state on the marked owner, or a one-way visibility marker on a decorative background. |

Use one source mode per image. A prepared list may include a prepared fallback URL. Reject ambiguous measured and prepared input before mutating the element. For deferred picture markup put media, type and dimensions on source elements and defer their srcset/sizes as on img. Native picture uses standard attributes throughout. Calls to enhance(le, root) accept a document, element or shadow root. Roots for markup discovery and for intersection are separate options. React and Lit attach within their own lifecycle. Skip their managed subtrees during auto-enhancement. An element-local, cross-copy ownership marker prevents duplicate attachment. Only its owner releases it. Shadow-root users can adopt the exported CSS string.

createLazyEase(config) returns an instance with attach(img, options) returning a handle with update(options) and destroy(). update starts a new generation on the same element and claim, and checks the new options that can throw (the observer's root and margin) before it ends the current one, so they leave the displayed image alone; a loader whose ladders are invalid (an empty or out-of-range list) still throws only when it is used, after the current generation ended; destroy followed by attach reaches the same result for a valid source change. The adapter renders initial static markup before hydration. After attach, the controller owns deferred source attributes, dynamic state, fade and placeholder styles. Re-renders must preserve those values. Destroy releases listeners, observers, timers and ownership. Adoption preserves an already displayed target of the same logical source (src, srcset, url, revision and deferred picture sources); the element remembers that source past destroy, so attaching it again with another one does not adopt the old image. A prepared image's logical source is its URL list, so a re-attach with other prepared URLs (a new quality or loader URL in React) returns to the placeholder and fades again, while a measured image keeps its src and upgrades the displayed image in place. Changing the logical source starts a new generation with its own placeholder. A native image's logical source is the URLs in its markup, so when React renders new ones into the same img (a new revision or token), it attaches again: the new source reports loading, then loaded or error, once, and a failed one is not swapped back to the old URL. The browser keeps showing the old image until the new one loads, and React paints no placeholder over it. A native data URI is a target and is adopted; only the inert pixel counts as a placeholder there. Stale completions cannot mutate that generation. Callbacks of the page follow one contract. An error thrown by onStateChange, onDisplay, a reveal or a deferred ThumbHash decode is reported from a timer, as an event listener's is, and the image goes on as if the callback had done nothing: attach and update neither throw it nor roll back. update and destroy inside any callback take effect at once, and the generation they ended writes nothing afterwards. The loader's url, detectFormat and the ThumbHash decoder are treated as pure functions: a loader that throws leaves the image on its placeholder, a detector that throws or rejects is reported and the image takes the format it would take without one, and a decoder that throws is an error of the attach or update that called it. Every call of `onStateChange`, `onDisplay`, `reveal` and the ThumbHash `lazy()` goes through one function (`guard`, in `dom/guard.ts`), and so does every subscription of an IntersectionObserver or ResizeObserver batch: a `whenVisible` callback or a measured image's loader that throws is reported from a timer, and the rest of the batch still runs, and React's render-time `lazy()` for `thumbhashSsr="image"` and `priority` catches the same way (on the server it logs the error with `console.error`, since a timer's error would end the process); `loader.url`, `detectFormat` and the decoder are called directly, as pure functions; `packages/core/test/callbacks.test.ts` and `packages/react/test/commits.test.tsx` hold the contract as tables.

## Display lifecycle

1. Show the placeholder before client code. Deferred images default to lazy with shared IntersectionObserver pools by root identity and effective margin. Keep the existing 400px default preload distance and optional dwell. Account for nested clipping. Dispose empty pools.
2. Use ResizeObserver content-box entries for measured images. Ignore zero-sized slots. Separate reads and writes, avoid synchronous layout and per-frame loops. Batch changes and preserve the existing trailing 200 ms resize debounce. Grow the offered ladder when needed. Browser crop needs the cover slot even if only the height grows.
3. Set visibility before activating target URLs. Apply sizes before srcset and coordinate picture sources and fallback to avoid interim requests. Suppress idle alt-text flash while keeping accessible text.
4. After successful load and decode, fade once (default 400 ms). Reduced motion or zero duration swaps directly. After a successful load, a bounded decode timeout may reveal directly. A failed initial load/decode releases the placeholder, restores error/alt presentation, preserves the reserved area and reports error. A placeholder known to stand for a transparent image fades out with the image (from 40 to 80 % of the fade, 25 to 60 % with a reveal) and is removed after the fade.
5. Keep the displayed target during resolution upgrades. An upgrade failure retains that image. Report idle, loading, loaded or error through onStateChange(state, img). Report first display once per logical source including successful cache adoption. React onLoad retains its event signature when an actual first load event is observed. Adoption never fabricates an event.
6. Native images remain visible through late enhancement. Priority implies eager discovery, high fetch priority and no fade. Match any responsive preload to the selected source, media, MIME type, candidates, sizes and credentials. At most preload the first eligible source under its own conditions. Prefer early picture markup when a matching preload adds no benefit.

No-JS fallback for deferred images is opt-in in both adapters. A noscript element helps with disabled scripting. A failed bundle leaves the deferred placeholder. Native HTML works in both cases. Native errors use browser presentation.

## Geometry, format and URL contract

Preserve fill, fixed, ratio and intrinsic layout modes. Emit CSS lengths with units in neutral style records. Use oriented source dimensions to reserve intrinsic article ratio even without a declared rendered width. Each art-direction source has its own media, source, dimensions, ratio, optional focal point and optional token. Supply breakpoint geometry on source and fallback images or through consumer CSS using aspect-ratio: var(--le-ar) on the box.

Server crop uses the nearest allowed ratio and the oriented crop window centered on the optional focal point, clamped to source edges. Normalize finite focus coordinates to integer percent (0–100); omit center. For browser crop request the uncropped source, use object-fit: cover and container-relative object positioning. Given source ratio R, use cover width max(boxWidth, boxHeight × R). Fill without an explicit ratio defaults to browser crop when both source dimensions are known, otherwise server crop when geometry can be measured. A native template with unknown crop geometry must supply an approved crop or uncropped fallback.

Keep the 0.2 default ladders: 13 widths from 64 to 3840, 73 ratios, quality 75. Custom small ladders and explicit format capabilities must work at both ends. Measured candidates cap at the ladder step for twice the effective slot. The browser selects the candidate. Fixed classic candidates offer snapped 1× and 2×. Free sizes can offer the full permitted ladder. Calculate actual output dimensions from oriented geometry, rounded crop window and no-upscale rules. Label each candidate with the actual encoded width, deduplicate identical outputs and emit a single src when appropriate. Without trusted metadata or a variant manifest, a single optimized URL is sufficient. That URL requests the largest candidate width for the slot.

createLoader accepts formats. Wherever NODE_ENV isn't "production" (development builds and Node without NODE_ENV set) it rejects ladders the reference backend would reject, with the backend's own construction check (checkLadders); production bundles drop that check to stay within the size budgets. Probe only declared formats when a choice is needed; a single format or an auto-negotiating third-party loader can bypass probing. The AVIF probe is opt-in (`detectFormat: detectAvif`), so a bundle without it carries no probe; without a detector a measured image requests the best declared format other than AVIF, except for a loader that declares only AVIF, which gets AVIF and no development warning. A single declared format never calls the detector. Explicit fmt is required on the reference backend. External URLs remain direct. Detect SVG by pathname extension or SVG data MIME type. Pass animated GIFs through; GIF with unknown animation status defaults to original. Preserve animation, layout and applicable lazy behavior. Optimized animation is a later release.

Reference URLs use encoded NFC source-path segments and ordered keys ar, fmt, fx, fy, q, token, v, w. Omit absent optional fields. Use canonical numbers (up to three decimal places, no exponent or trailing zeros); preserve case of opaque values. Emit q explicitly. Keep one spelling per public variant or normalize before cache lookup. Validate configured widths, ratios, formats and quality before rendering. Reject inconsistent focus and ambiguous or malformed input. A crop token is optional, scoped to source identity, revision and crop including focus. Width, format and quality remain bounded independently. Define interoperability bytes and matching fixtures before enabling signing. Viewer authentication is a separate check.

For one revision with all default crops admitted, the upper bound is 13 × 3 × (1 + 73 × 101²) = 29,042,286. A single approved crop admits at most 39 outputs with the default width/format/quality sets. Configure finite per-source crop permissions in public tokenless mode. See the [backend guide](backend.md) for storage and capacity requirements.

## Verification

Require unit, cross-language fixture, packed-package and real-browser coverage. Browser fixtures cover first paint, disabled and failed JS, event adoption, accurate descriptors, nested scroll roots, destruction, several bundles, Shadow DOM, reduced motion, Firefox/Chromium/WebKit and request counts through resize and breakpoint changes. Measure LCP, CLS and interaction latency on a separate lightweight page. Report environment and trace methodology. A lab trace or Lighthouse TBT is not field INP. Compare delivery bytes and variant counts at 1× and 2× before revising ladders.
